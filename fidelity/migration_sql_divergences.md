# Migration SQL differential harness and divergences

`migration_sql_test.go` collects Djan-Go-Go migration DDL via
`migrations.Loader.CollectSQL` for 25 canonical operations across both SQLite
and PostgreSQL, comparing normalized statements against checked-in Django 6.0.3
goldens in `golden/migration_sql/sqlite.json` and
`golden/migration_sql/postgres.json`.

In addition:

- **SQLite semantic schema check**: every case executes on a fresh in-memory
  SQLite database via `migrations.Apply` and compares the resulting schema
  (`PRAGMA table_info`, `PRAGMA index_list`, `PRAGMA index_xinfo`,
  `PRAGMA foreign_key_list`) against Django's resulting schema. SQLite
  table-rebuild operations (`add_field_default_*`, `alter_field_*`,
  `remove_field`) are verified through this semantic schema check rather than
  textual SQL comparison.
- **PostgreSQL live execution**: `TestMigrationPostgresExecution` applies every
  case against a private schema in PostgreSQL when `DJANGOGO_TEST_POSTGRES_DSN`
  is set, confirming all generated DDL executes cleanly.

## Regenerating goldens

Run from the repository root with Python 3 and Django installed:

```
go generate ./fidelity/...
```

or specifically for migration SQL:

```
python3 fidelity/oracle/migration_sql.py
```

SQLite cases run against an in-memory SQLite database. PostgreSQL SQL is
compiled offline through Django's real PostgreSQL schema editor
(`pg_version = 160000`) with a minimal `psycopg` shim and pre-migration
constraint metadata derived from the `ProjectState`, so no live PostgreSQL
server or Python driver is required.

## Documented DDL normalization

Before comparing non-rebuild SQL statements, `normalizeMigrationSQL` applies
three transformations outside single-quoted SQL string literals:

1. **Identifier quoting**: simple double-quoted identifiers
   (`"migfid_article"`) are unquoted.
2. **Case folding**: SQL keywords, type names, and lowercase snake_case
   identifiers are lowercased outside string literals (`VARCHAR(100)` and
   `varchar(100)` compare equal).
3. **Whitespace and trailing semicolon**: runs of whitespace collapse to one
   space, padding around parentheses and commas is normalized, and trailing
   semicolons are stripped.

## SQLite semantic schema comparison

`compareSQLiteSchemas` compares resulting SQLite schemas after applying setup
and target migrations:

- Exact table name set.
- Exact column name set per table (order-independent, since Django's SQLite
  rebuild moves altered columns to the end while Djan-Go-Go preserves field
  order), normalized column type (`boolean` == `bool`), `pk`, and `notnull`
  (excluding `INTEGER PRIMARY KEY`, which is implicitly non-null in SQLite).
- Exact index coverage set (unique flag + ordered column list including `DESC`).
- Exact foreign-key target set (`from -> table.to`, excluding `on_delete`
  action since Django enforces `on_delete` in Python while Djan-Go-Go enforces
  it via SQL `ON DELETE`).

All 29 cases pass SQLite schema equivalence with zero schema divergences.

## Allowlisted DDL divergences

Every non-rebuild case below passes SQLite schema equivalence and live
PostgreSQL execution. The test fails if an allowlisted case begins matching
Django so stale entries are caught and removed.

### Shared (SQLite and PostgreSQL)

| Cases | Django 6.0.3 | Djan-Go-Go |
| --- | --- | --- |
| `create_model_fk_and_meta`, `add_field_fk` | Emits `DEFERRABLE INITIALLY DEFERRED` with no `ON DELETE` clause (on PG, defers `ADD CONSTRAINT ... FOREIGN KEY` or appends `SET CONSTRAINTS ... IMMEDIATE`); enforces `on_delete` in Python | Emits inline table `FOREIGN KEY (...) REFERENCES ... ON DELETE ... DEFERRABLE INITIALLY DEFERRED` (in `CreateModel`) or inline `REFERENCES ... ON DELETE ... DEFERRABLE INITIALLY DEFERRED` (in `AddField`) so the database enforces `on_delete`; emits `unique_together` after indexes |
| `add_field_nullable` | Writes explicit `NULL` (`ADD COLUMN "subtitle" varchar(120) NULL`) | Omits implicit `NULL` (`ADD COLUMN "subtitle" VARCHAR(120)`) |
| `rename_model_with_fk` | Emits only `ALTER TABLE "migfid_article" RENAME TO "migfid_post"` | Also renames derived indexes (`DROP INDEX` + `CREATE INDEX` on SQLite; `ALTER INDEX ... RENAME TO ...` on PG) so later operations find them without introspection |

### SQLite only

| Cases | Django 6.0.3 | Djan-Go-Go |
| --- | --- | --- |
| `create_model_basic`, `create_model_all_kinds` | Emits `"id" integer NOT NULL PRIMARY KEY AUTOINCREMENT`, `bool`, explicit `NULL` on nullable columns, and double parens in `CHECK ((JSON_VALID("json_val") OR "json_val" IS NULL))` | Emits `"id" INTEGER PRIMARY KEY AUTOINCREMENT`, `BOOLEAN`, omits implicit `NULL`, and uses single parens in `CHECK (JSON_VALID("json_val") OR "json_val" IS NULL)` |

### PostgreSQL only

| Cases | Django 6.0.3 | Djan-Go-Go |
| --- | --- | --- |
| `create_model_basic`, `create_model_all_kinds` | Uses `bigint NOT NULL PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY`, `integer` for `IntegerField`, `timestamp with time zone`, explicit `NULL`, and companion `varchar_pattern_ops` (`_like`) indexes on indexed/unique `varchar` columns | Uses `BIGSERIAL PRIMARY KEY`, `BIGINT` for `KindInt` (64-bit Go `int`), `TIMESTAMPTZ` synonym, omits implicit `NULL`, and omits `_like` indexes |
| `add_field_default_int`, `add_field_default_char`, `add_field_default_bool` | Emits `ADD COLUMN ... DEFAULT <val> NOT NULL` (and `integer` for `IntegerField`) | Emits `ADD COLUMN ... NOT NULL DEFAULT <val>` (and `BIGINT` for `KindInt`) |
| `alter_field_null_to_not_null` | Emits `SET DEFAULT`, `UPDATE ...; SET CONSTRAINTS ALL IMMEDIATE`, `SET NOT NULL`, `DROP DEFAULT` | Emits `UPDATE ... WHERE col IS NULL` then `SET NOT NULL` |
| `alter_field_add_unique`, `alter_field_remove_unique` | Creates/drops companion `varchar_pattern_ops` `_like` index alongside `UNIQUE` constraint on `varchar` columns | Emits only `ADD CONSTRAINT ... UNIQUE` / `DROP CONSTRAINT` |
